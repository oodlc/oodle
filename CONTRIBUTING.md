# Contributing

Thanks for helping with OODLC and Oodle.

## Setup

```bash
npm install
npm test             # seeded scenarios in test/scenarios.test.ts
npm run typecheck
```

## Changing the model

Some changes alter what OODLC *means*: what blocks a merge, what an outcome, behavior or constraint is, or the shape of `spec/catalog.schema.json`. Those need a decision record in [`docs/decisions/`](docs/decisions/) in the same PR. Read the existing ones first; [0001](docs/decisions/0001-outcomes-and-behaviors.md) and [0002](docs/decisions/0002-constraints-hold-on-every-run.md) set the core rules:

- Only what a human declared can block: **outcomes** and **constraints**.
- What the runner observed (**behaviors**) is reported, never blocking on its own.

Each rule has a scenario in `test/scenarios.test.ts`. A change that alters one should change its test and its record together.

## Oodle

Oodle's voice is calm and plain. It's allowed to be pleased by a tidy catalog, but it never makes light of real breakage. Oodle writes only to stderr, so stdout stays machine-readable. The artwork is generated by `scripts/oodle-art.py`; edit the script, not the SVGs.
